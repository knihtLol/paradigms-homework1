------------------------------------------------------------
3. How I used them (2%)
------------------------------------------------------------
My use of Claude in Part II covered the following kinds of
assistance:

1. Learning unfamiliar syntax: when I encountered Python constructs
   I was not familiar with (e.g., dictionary comprehensions,
   **kwargs, str.rsplit, dict.pop with a default,
   BaseHTTPRequestHandler mechanics), I asked Claude to explain
   what they do and how they work, with examples.

2. Converting my header file to gSOAP syntax: I first wrote the
   Chat Room contract as plain C structs and function prototypes
   myself. I then shared my C header with Claude and asked it to
   rewrite it in the //gsoap-directive syntax expected by the
   soapcpp2 tool (the ns__ prefix convention, __size-prefixed array
   fields, and the operation prototype format), which generated
   soap_chatApi.h.

3. Understanding the server-side connection in Part II: I used
   Claude to review and explain how the HTTP/SOAP connection layer
   works in the server (how BaseHTTPRequestHandler receives POST
   requests, how handle() dispatches an XML operation name to a
   Python function, and how the reply envelope is built), so I
   could understand how the whole request/response path operates
   end to end before writing and adapting my own code.

4. Reviewing and modifying server.py and client.py: the original
   single-file server.py had become too large and heavy to navigate
   and maintain, so I asked Claude to review it and suggest a
   cleaner structure. Based on that review, server.py was divided
   into multiple modules - state.py (shared in-memory data),
   logic.py (the eleven operations), soap.py (XML rendering and
   dispatch), http_layer.py (HTTP handling), and main.py (entry
   point). Claude also reviewed and modified client.py, simplifying
   and cleaning up the interactive command loop and the
   response-unwrapping helpers.
